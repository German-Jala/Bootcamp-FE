Cars - Array From Static Data

The actual behavior: Angular doesn't magically know that the variable has changed. However, because you're using the traditional Change Detection system (Zone.js), Angular re-evaluates the entire component when an asynchronous event (like the interval) occurs. Upon noticing that the array reference has changed, the {{ '@for' }} loop reprocesses the list.

Verdict: It works well for data that changes infrequently, but it relies on Angular constantly checking the entire component.

@for(car of carsArray; track $index) {
{{ car.model }}
{{ car.price }}
}

Cars - Array From Function

How it works: You're calling a function directly within the HTML template.

The major performance hazard: Every time Angular performs any change detection cycle (for example, if you move the mouse, click, or time passes), it re-executes the function.

What happens every 5 seconds: It's not just running every 5 seconds; it's running dozens of times in the background. Because your function returns a new array ([...]) each time it's called, Angular gets confused, thinking the data has changed infinitely.

@for(car of carsArrayInFuction(); track $index) {
{{ car.model }}
{{ car.price }}
}

Cars - Array From a Observable

How it works: It uses the Observer/Observable pattern. The HTML "subscribes" to this channel using the async pipe.

What happens every 5 seconds: Your component emits a new block of data through the channel with `.emit()`. The async pipe detects this emission, notifies Angular that there is new data, and updates the `{{ '@for' }}` loop.

@for(car of $carsObservable | async; track $index) {
{{ car.model }}
{{ car.price }}
}

Cars - Array From Signal

How it works: It's Angular's new native approach (Signals). A signal is a container that knows exactly who is consuming its value.

What happens every 5 seconds: You use `.update()`. Angular immediately detects that the value has changed.

The big difference: Unlike Approaches 1 and 2, Angular doesn't need to check the entire component. It knows with pinpoint accuracy that `carsSignal` has changed and only needs to update that specific part of the HTML.

Verdict: The best option currently available. It's the modern Angular standard, ultra-fast, and memory-efficient.

@for(car of carsSignal(); track $index) {
{{ car.model }}
{{ car.price }}
}
